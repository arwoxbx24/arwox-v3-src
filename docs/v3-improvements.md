## КРИТИЧНО — нарушения правил ТЗ

### 1. [P0] Отсутствует блок «3 краткие карточки результата» перед сценариями
**Нарушение:** technical_prompt п.4 явно требует: «сначала 3 короткие карточки результата, ниже — 3 детальных сценария». Мокап 01 это подтверждает — над карточками сценариев стоят 3 stat-карточки.
**V2:** Секция Results сразу открывает 3 полных сценария без intro-результатов.
**V3:** Добавить горизонтальную полосу из 3 stat-карточек после заголовка: «+47% рост продаж», «−32% снижение издержек», «+28% точные данные» (или по аналогии с мокапом 01 — три метрики из реальных сценариев). Карточки — compact, без scroll, в одну строку на десктопе.

### 2. [P0] Отсутствует секция «Как мы внедряем Bitrix24» (6 шагов)
**Нарушение:** Текстовый контент (landing_text_content.md, строки 399–451) содержит 6 шагов с текстами. Мокап 02 показывает горизонтальный timeline 01→06. V2 эту секцию полностью пропускает.
**V3:** Добавить секцию с 6 numbered steps между WhyUs и Integrations: Диагностика → Разработка ТЗ → Запуск и демонстрация → Сдача проекта → Обучение и тестирование → Подписание актов. Визуально: горизонтальная цепочка с нумерованными иконками и соединительной линией на десктопе, вертикальный список на мобиле.

### 3. [P0] Типографика H1 слабее мокапа — weight 700 вместо 800–900
**Нарушение:** technical_prompt: «H1 desktop: 64–76px, weight 800–900». V2 использует `font-bold` (700). Мокап 01 показывает очень жирный H1 с видимым разрывом в насыщенности между телом и заголовком.
**V3:** H1 → `font-extrabold` (800) или `font-black` (900). H2 всех секций → `font-extrabold`. Размер H1 на десктопе фиксировать не ниже `text-7xl` (4.5rem ≈ 72px).

### 4. [P0] Бейджи компетенций Hero — слишком компактные, не соответствуют мокапу
**Нарушение:** Мокап 01 показывает 4 крупные карточки с большими иконками (≥48px контейнер), явными подписями и выраженными тенями. В v2 карточки сжаты, иконки маленькие (size-10), нет ощущения «веса».
**V3:** Переделать в крупные карточки: icon-контейнер ≥ size-14 (56px), явный gradient-icon как в мокапе (голубой → синий → фиолетовый), заголовок крупнее (text-sm → text-base), добавить `hover:shadow-md hover:-translate-y-0.5 transition` для всех четырёх. Минимальная высота карточки ~80px.

## ВЫСОКИЙ — визуальные дефекты против мокапа

### 5. [P1] Кейс санатория — верстка не соответствует мокапу 02
**Проблема:** Мокап 02 показывает: полная фотография санатория на всю ширину с оверлеем «Заявки в одном окне», ниже — горизонтальная строка из 5 иконок-метрик (30 дней, 50 человек, 1 окно, real-time, ×0), затем цитата с аватаром на белом фоне. V2 верстает это как 2-колоночный grid с маленькой фото слева и 3-колоночным контентом справа — выглядит мельче и слабее мокапа.
**V3:** Реализовать по мокапу: фото на полную ширину (~400px high) с dark gradient overlay и заголовком поверх, ниже 5 stat-иконок в строку, затем секции задача/решение/результат в три колонки, цитата отдельной полосой с bg-surface-soft.

### 6. [P1] WhyUs — в мокапе 02 пять преимуществ, в v2 — четыре
**Проблема:** Мокап 02 явно показывает 5 карточек в секции «Почему ARWOX» (5-я: «Гарантия результата»). V2 рендерит только 4.
**V3:** Добавить 5-ю карточку: «Гарантия результата» — «Фиксируем договорённости документально. Результат подтверждается актами на каждом этапе.»

### 7. [P1] Нет hover-состояний на карточках — нарушение UX-правил
**Нарушение:** technical_prompt: «Все CTA и интерактивные элементы должны иметь hover/focus states». V2 — карточки сценариев, карточки WhyUs, иконки интеграций, карточки тарифов, accordion-пункты FAQ — без hover-эффекта.
**V3:** На всех card-элементах: `transition-all duration-200 hover:shadow-lg hover:-translate-y-0.5 cursor-default`. Для интерактивных ссылок и кнопок в header: `transition-colors duration-150`. Accordion: уже есть hover в shadcn, проверить что работает.

### 8. [P1] Интеграции — иконки в мокапе с логотипами, в v2 — только lucide/текст
**Проблема:** Мокап 03 показывает в блоке интеграций реальные узнаваемые иконки сервисов (1С, телефония, WhatsApp, Telegram, Email, API). В public/assets/icons/ уже лежат 20 SVG-иконок. V2 использует только lucide-react иконки, не задействуя фирменные SVG-ассеты.
**V3:** Заменить иконки блока интеграций на фирменные SVG из /assets/icons/: использовать через `<img src="/assets/icons/whatsapp.svg" />` и аналоги. Для отсутствующих — оставить lucide, но визуально унифицировать размер.

### 9. [P1] Тарифы: в мокапе 03 Энтерпрайз = «По запросу», в v2 — цена 11 890 ₽
**Проблема:** Мокап 03 показывает для тарифа Энтерпрайз кнопку «По запросу» без фиксированной цены. V2 выводит 11 890 ₽.
**V3:** Энтерпрайз-карточку изменить: вместо числовой цены — «По запросу» + CTA-кнопка «Обсудить». Цены остальных 3 тарифов — как в landing_text_content.md.

## СРЕДНИЙ — несоответствия UX/контент

### 10. [P2] Секция Websites — названия форматов и тайминги расходятся с мокапом 04
**Проблема:** Мокап 04 называет форматы «Классический сайт» и «MVP и быстрый старт» (не «Формат А» / «Формат Б»). Также показывает срок «от 20 дней» и «от 7 дней» — этой информации в v2 нет.
**V3:** Переименовать карточки по мокапу. Добавить сроки. Изменить иконки: в мокапе первая карточка использует синюю SVG-иконку сайта, вторая — иконку ракеты/AI.

### 11. [P2] Форма контакта — в мокапе 04 тёмно-синий hero-фон, в v2 — светлый card
**Проблема:** Мокап 04 показывает Contact-секцию с тёмно-синим левым блоком (dark gradient) и белой формой справа на общем dark-blue фоне — выглядит как финальный CTA-акцент. V2 рендерит светлую карточку на `bg-surface-soft` — слабый визуальный акцент перед футером.
**V3:** Изменить секцию Contact: левая половина — `dark-scope` с тёмно-синим градиентом, текст/иконки белые. Правая половина — форма на белом bg с лёгкой тенью. Общий wrapper секции — `dark-scope` или насыщенный `bg-hero` с gradient glow.

### 12. [P2] Футер — в мокапе 04 есть иконки соцсетей и колонка «Компания»
**Проблема:** Мокап 04 показывает в футере 4 колонки: ARWOX, Услуги, Компания (FAQ / Соглашение / Политика данных), Контакты + иконки соцсетей (ВКонтакте, Telegram, WhatsApp). V2 называет колонку «Помощь» и не включает иконки соцсетей.
**V3:** Переименовать «Помощь» → «Компания». Добавить иконки соцсетей в контактную колонку футера (ВК, Telegram, WhatsApp) с hover-эффектом.

### 13. [P2] Блок BitrixGPT — GPT-тарифы ниже основного блока дублируют Tariffs
**Проблема:** V2 рендерит два раздела с тарифами: внутри BitrixGPT (4 тарифа GPT) и отдельная секция Tariffs (4 тарифа лицензий). Это нарушает правило «не дублировать блоки». Мокап 03 показывает тарифы в одной секции — «Тарифы Битрикс24» — без GPT sub-тарифов под BitrixGPT.
**V3:** Убрать GPT sub-тарифы из секции BitrixGPT. Оставить только маркетплейс-CTA. Тарифная секция остаётся единственной.

### 14. [P2] Hero: контактные ссылки под кнопками дублируют Header
**Проблема:** V2 в Hero рендерит телефон и email прямо под CTA-кнопками — они уже есть в header. Мокап 01 контактные данные в Hero не дублирует.
**V3:** Убрать дублирующие ссылки телефона/email из Hero-блока. Вместо них можно добавить один «доверительный элемент» — например, бейдж «14 дней — среднее время запуска» или счётчик «50+ внедрений».

## НИЗКИЙ — детали и полировка

### 15. [P3] Текст «Что меняется» — заголовок секции не должен переноситься посередине слова
**V2:** `Что меняется после <br /> внедрения Битрикс24` — принудительный перенос. Мокап 01 показывает одну строку без разрыва.
**V3:** Убрать `<br />`, использовать `text-balance` или `max-w-2xl mx-auto` для естественного переноса.

### 16. [P3] DashboardMock — нет мобильной адаптации, на 360px переполнение
**Проблема:** DashboardMock использует `grid-cols-4` для KPI-плиток и `grid-cols-2` для графиков — на 360px оба ломаются. Мокап показывает dashboard только на десктопе, но адаптив обязателен по ТЗ.
**V3:** На мобиле dashboard скрывать (`hidden lg:block`) или упрощать до 2 KPI-строк + воронки. Добавить `overflow-hidden` на всём wrapper.

### 17. [P3] Pill-компонент — использует `bg-white` и `text-brand` без dark-scope адаптации
**Проблема:** Внутри тёмных секций (Integrations, BitrixGPT) Pill-компонент не переключается в dark-режим — белый фон режет глаз на тёмном bg. V2 в тёмных секциях переопределяет Pill вручную через отдельный inline div.
**V3:** Pill получает вариант `variant="dark"` или использует CSS-переменные через dark-scope `.dark-scope .pill { bg: white/10; color: brand-2 }`. Единый компонент на всей странице.

### 18. [P3] Accordion FAQ — нет визуального разделителя между вопросами, они сливаются
**Проблема:** V2 использует `space-y-3` между AccordionItem, но нет border-bottom при закрытом состоянии — при `collapsible` все вопросы выглядят как один блок.
**V3:** AccordionItem добавить `border border-border` и `divide-y divide-border` для явного разделения строк.

### 19. [P3] Мета-теги — og:image отсутствует
**Проблема:** V2 не включает `og:image` в head(). Для шеринга в мессенджерах страница не будет иметь превью.
**V3:** Добавить `{ property: "og:image", content: "/assets/images/og-preview.png" }` и создать заглушку 1200×630.

### 20. [P3] CSS-переменная `--dark-blue-2` используется в JSX через `style={}` вместо утилиты
**Проблема:** `style={{ background: "var(--dark-blue-2)" }}` в BitrixGPT section — нарушает единообразие с Tailwind-токенами. В styles.css уже должен быть класс `bg-dark-blue-2`.
**V3:** Убрать все inline `style={{ background }}` в пользу CSS-классов. Если класса нет — добавить в styles.css.
