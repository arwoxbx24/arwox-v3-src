2. Различать класс отказа `crm.lead.add`: временный (URLError, таймаут, HTTP 429, 5xx) и по содержанию (4xx кроме 429, `error` в JSON). Минимальная правка `call_b24` или флаг из неё — на усмотрение, сигнатура для прочих вызовов прежняя.
3. Временный отказ и задан `LEAD_SPOOL_DIR` → записать `{"fields":…, "ctx":…, "attempts":0, "created":<epoch>}` в `<LEAD_SPOOL_DIR>/<secrets.token_hex(8)>.json`: каталог создать 0700, umask 077 (файл 0600), запись `*.tmp` + `os.replace`. Ответ — прежний редирект успеха по `form_content`. В каталоге ≥500 `*.json`/`*.inflight` → прежний `?err=server#contact`. Без `LEAD_SPOOL_DIR`, при отказе по содержанию или ошибке записи — прежний `?err=server#contact`.
4. Функция `drain_spool(spool_dir, now=None)`: для каждого `*.json` — rename в `*.inflight`; битый JSON, `created` старше 24 ч или `attempts >= 100` → перенос в `failed/` (0700) и строка лога; иначе `create_lead(fields, ctx)`: успех → файл удалить; временный отказ → `attempts+1`, записать и вернуть имя `*.json`; отказ по содержанию → `failed/`. Один битый файл не останавливает остальные. При старте `drain_spool` осиротевшие `*.inflight` возвращаются в `*.json`.
5. Логи очереди (stderr): только id файла, счётчики, класс/код ошибки. Поля заявки, телефон, e-mail, IP, тело ответа Bitrix24 — не печатать.
