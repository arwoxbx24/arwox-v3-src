## U1. `forms-failover/demo.sh` — чек-лист из 5 этапов
Этапы (одинаковые подписи везде):
1. Сбой Яндекса имитирован
2. Сторож заметил сбой (в журнале сторожа `check code=000` или `debounced outage` после старта)
3. DNS переключён на резерв (все 6 NS Beget = `$BEGET_IP`)
4. Сертификат на резерве готов (`curl -s -o /dev/null --max-time 10 --resolve "$FQDN:443:$BEGET_IP" "https://$FQDN/"` rc 0)
5. Заявка принята резервом (существующая проверка POST, `demo.sh:91-103`)

- В цикле ожидания (каждые 15 с — как сейчас; печать на экран не реже 60 с) печатать одну строку прогресса: `[+M мин] Этап N/5: <подпись> ⏳ | DNS k/6 | сторож: <последнее событие по-русски>`; при прохождении этапа — строку `✅ Этап N/5: <подпись> (+M мин)`. Финал: `🏁 Тест пройден: 5/5 за M мин` либо `❌ Этап N/5: <причина>` и выход ≠ 0.
- Журнал сторожа: переменная `GUARD_LOG` (по умолчанию `/root/.pm2/logs/forms-gw-guard-test-out.log`); читать только строки после момента старта `simulate`. Перевод событий: `check code=000` → «форма не отвечает»; `debounced outage` → «сбой подтверждён»; `sent fallback_outage` → «резерв включён»; `ssl request rc=0` → «сертификат запрошен»; `ssl request rc=` ≠0 → «сертификат: ошибка, повтор через 15 мин»; иначе — строка как есть.
- Ранний стоп: строка `dns switch failed: <X>` в журнале сторожа после старта → `❌ Этап 3/5: переключение DNS отклонено: <X>`, выход 1.
- Этап 4: ожидание с тем же прогрессом, потолок 20 мин (как `wait_for`).
- `status`: `backup_code` — GET по http, `--resolve "$FQDN:80:$BEGET_IP"`, печатать код (ожидается 302).
- Записи в `demo.log` (`record`) сохранить.
