# ТЗ dcfg-1ci20.23 — forms-gw-guard: снимок инцидента при переходе в outage (spec:103 v3)

Исполнитель пишет код сам, code-channel не вызывает. Разведка — repowise (индекс: repowise/CBM проверен, нет — `tools/bin/code-memory-enable`). Секреты не читать и не писать в снимок. Сеть, API, pm2, docker не вызывать. Принципы: KISS, YAGNI, SoC, fail fast; без правок соседнего кода.

## ADR
Вариант A — функция в `forms-gw-guard.sh`, вызов в момент перехода `fallback_track` в `outage`. Отвергнут B — отдельный скрипт: второго потребителя нет (YAGNI). Отвергнут C — постоянный расширенный журнал: лишний объём, данные нужны только в момент сбоя.

## U1. Правка `forms-failover/forms-gw-guard.sh`
1. Функция `incident_snapshot()`:
   - каталог `$GUARD_STATE_DIR/incidents/<UTC YYYYmmddTHHMMSSZ>/`;
   - файлы: `curl.txt` — `curl -sv --max-time 15` проверки формы с теми же `--resolve`, что в `check_form` (stdout+stderr, заголовок `Authorization` в выводе отсутствует — curl его не шлёт); `dns.txt` — `dig +short "$GUARD_FQDN" @<ns>` по 6 NS Beget (тот же список, что в шаге LE); `guard.txt` — `tail -n 50` файла `$GUARD_LOG_FILE`, если переменная задана и файл читается, иначе строка `no log`;
   - каждая команда с `|| true`: снимок не роняет сторожа;
   - хранить не больше 10 каталогов в `incidents/`, старые удалять (`ls -1d` по имени, сортировка по имени = по времени);
   - печатать путь каталога в stdout.
2. В `fallback_track`, ветка `outage` (сейчас строка 179): перед `notify fallback_outage` вызвать снимок и добавить в текст уведомления ` Снимок: <путь>`.
3. `docker logs` и журналы NPM не читать (в них закрытые ключи, dcfg-1j117).

## U2. Тест `forms-failover/forms-gw-guard-test.sh`
Добавить кейсы в существующем стиле (подменные `curl`/`dig` уже есть в тесте):
- переход в outage → появился ровно 1 каталог `incidents/*` с 3 файлами, путь есть в тексте уведомления;
- переход в normal → новых каталогов нет;
- 12 переходов в outage → каталогов 10.

## Критерии
1. `bash -n forms-failover/forms-gw-guard.sh` rc 0; `bash -n forms-failover/forms-gw-guard-test.sh` rc 0.
2. `bash forms-failover/forms-gw-guard-test.sh` → `PASS N/N`, N > 19.
3. `grep -c 'docker logs' forms-failover/forms-gw-guard.sh` = 0.
4. `git diff --stat` — только 2 файла.
