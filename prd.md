# PRD — arwox-v3-src

## Проблема
Заявки клиентов с сайта arwox.ru должны попадать в Bitrix24 без потерь, в том числе при аварии Yandex Cloud (авария 08.10.2026, зона ru-central1-b: https://www.comss.ru/page.php?id=22333).

## Пользователи
- Клиент arwox.ru — оставляет заявку в форме (телефон, имя, согласие на обработку ПДн).
- Менеджер — получает лид в Bitrix24.
- Владелец — видит результат, команд не запускает.

## Фичи
1. Лендинг arwox.ru (React/TypeScript, `src/`).
2. Приём формы: обработчик `site78-releases/2026-07-29/backend-arwox-lead-form/index.py` — функция Yandex Cloud за API Gateway `forms.arwox.ru`; капча SmartCaptcha; согласие ПДн обязательно.
3. Резерв форм `forms-failover/`: тот же обработчик на нашем сервере (pm2 `forms-backup`), очередь заявок при отказе Bitrix24, пометка лида фразой сбоя.

## Требования качества
- Ноль потерянных заявок: отказ Bitrix24 → очередь резерва; отказ Yandex Cloud → резерв на нашем сервере.
- Согласие ПДн обязательно и доказуемо (152-ФЗ); ПДн и секреты не попадают в логи, bd и git.
- Изменения форм проходят тест-стенд `forms-test.arwox.ru` до боевого адреса.

## Критерии эпика устойчивости форм (bd, 08.10)
1. При недоступности шлюза кнопка формы открывает готовую CRM-форму Bitrix24 — проверка на тестовом стенде.
2. Алерт сбоя несёт класс (инфраструктура / архитектура / код) и признак каскада.
3. Подробный журнал включается только при сбое.
4. Регламент yc CLI: команды из реестра, ноль неизвестных подкоманд за неделю.

## Ограничения владельца
- Без новых платных сервисов.
- Без новых скриптов-дублей; доработка существующего.
- Без своих процессов опроса для переключения (приказ 09.10).
- Технические решения — агент, запись в bd; вопросы владельцу — только о цели.

## Трекинг
Задачи — только bd (эпик `dcfg-1ci20`, spec:103). Решения и находки — `bd remember` и заметки атомов. Отдельных `tasks.md`/`memory.md` нет — это дубли bd.
