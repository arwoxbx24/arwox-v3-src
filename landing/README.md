# Лендинг arwox.ru в файлах

Код страниц Битрикс24 хранится здесь и выкладывается отсюда на сайт. Источник правды — эти файлы, не редактор Битрикс24.

| Каталог | Сайт Битрикс24 | Адрес | Страницы |
|---|---|---|---|
| `site78/` | 78, prod | https://arwox.ru | 13: lid 362 (главная), 374–396 |
| `site80/` | 80, dev (noindex) | https://b24-w7skc9.bitrix24site.ru | lid 368 (dev-главная), 372 (только снимок) |

Файлы страницы `site<SITE>/<lid>/`:
- `block-<id>.draft.html` — черновой блок (`landing.block.getlist`, `edit_mode=1`), как вернул Битрикс24, вместе с обёрткой `<div id="b<id>" …>`;
- `block-<id>.public.html` — опубликованный блок (`edit_mode=0`), id у него свой;
- `additional-fields.json` — `landing.landing.getadditionalfields` целиком;
- `cssblock.css` — поле `CSSBLOCK_CODE` из него (CSS страницы), для правок и диффа.

## Команды

```bash
bash landing/b24-landing.sh snapshot 78 landing/site78   # снять сайт в файлы (заменяет каталог)
bash landing/b24-landing.sh verify 78 landing/site78     # сверить живой сайт с файлами: ok=N failed=M
bash landing/b24-landing-test.sh                         # тесты скрипта (заглушка b24, без сети)
```

Правило: до любой записи в Битрикс24 живое состояние снято сюда и `verify` даёт `failed=0`. Правка в редакторе Битрикс24 мимо репозитория обнаруживается `verify` и сначала снимается в git.

Снимок 21.10.2026: `verify 78` → `ok=64 failed=0`, `verify 80` → `ok=8 failed=0`; CSS lid 362 — 64 723 символа.

## Выкладка и откат

Полные правила — `AGENTS.md`, раздел «Landing dev/prod»; здесь только команды и порядок.

- `deploy dev` — файлы главной с HEAD → dev-страница 368, формы → forms-test; сначала `verify 80` = git, иначе отказ.
- `deploy prod` — файлы главной с origin/main → прод-страница 362, затем новый тег `landing-prod-*`; только при HEAD = origin/main.
- `rollback <tag>` — файлы главной из тега `landing-prod-*` → страница 362, затем новый тег.
- `check <url>` — живая страница: 15 секций по порядку, 3 из 3 форм на адрес своей среды, размер CSS.

Граница: выкладывается только главная, 362 (прод, сайт 78) → 368 (dev, сайт 80). Страницы 374–396 — только снимок.

Перед каждой записью все `action=` форм должны вести на адрес формы среды (прод `https://forms.arwox.ru/`, dev `https://forms-test.arwox.ru/`), а CSS — влезать в 65 535 байт.

Сверка прода с тегом: `deploy prod` отказывает без тега `landing-prod-*` и когда живая страница 362 отличается от последнего тега; неудачная запись возвращает версию тега.

Базовый тег — после слияния PR и только если `verify 78 landing/site78` → `failed=0`: `git tag landing-prod-<UTC YYYYmmdd-HHMMSS>-<короткий sha> <sha слияния>`, затем `git push origin refs/tags/<тег>`.

После любой выкладки — `snapshot` этого сайта и коммит.

## Замеры REST (21.10.2026, только dev: сайт 80, lid 368)

| Что проверяли | Действие | Результат |
|---|---|---|
| Запись того же содержимого | `landing.block.updatecontent` блока 9220 исходным HTML без обёртки | `true`; `verify 80` → `ok=8 failed=0` — запись без изменений ничего не меняет |
| Автопубликация | `updatecontent` с маркером `<span data-probe="dcfg-n59cp" hidden>` | маркер в черновике 9220 есть, в публичном 9222 нет, на живой странице 0 вхождений — REST пишет только черновик |
| Публикация | `landing.landing.publication lid=368` | маркер в публичном блоке и на живой странице; id публичного блока остался 9222 |
| Нормализация HTML | сравнение отправленного и перечитанного без обёртки `<div id="b…">` | 221 469 символов, черновик и публичный блок равны отправленному побайтно — Битрикс24 HTML не меняет |
| Лимит `CSSBLOCK_CODE` | `landing.landing.update` с CSS 65 535 символов (65 569 байт) | ответ `true`, сохранено 65 501 символ = 65 535 байт, начало отправленного — **лимит 65 535 байт UTF-8, лишнее молча обрезается**; остальные поля страницы не изменились |
| Возврат | исходный CSS, исходный черновик, `publication` | `verify 80` → `ok=8 failed=0`; живая страница 200, 331 373 байта — как до замеров |

Сайт 78 (прод) в замерах не участвовал. Запас CSS главной прода: 64 723 символа = 64 757 байт, до лимита 778 байт. Поэтому `deploy` проверяет длину CSS в байтах (`wc -c`) до записи и сверяет CSS после записи.
